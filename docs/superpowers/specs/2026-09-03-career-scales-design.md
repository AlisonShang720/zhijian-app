# 生涯测评模块接入可作答量表 —— 设计文档

日期：2026-09-03
范围：`zhijian-app.html`（单文件 H5 原型，约 2337 行）

## 1. 背景与目标

本项目是一个"生涯探索 AI 助手"的高保真移动 App 原型，全部内容在单个 HTML 文件内。首页「生涯趣测」3×3 网格与「测评」页（`page-assess`）共列出 10 个测评入口，但其中只有「生涯规划测评」真正可作答（长页 13 题 → 静态示例结果），其余入口点击仅弹 `showToast` 占位。

本次目标：把以下 **3 个入口**做成真实可作答的测评，UI 完全沿用本项目现有风格：

| 入口 | 打开后应提供 |
|---|---|
| **性格测评** | 性格类量表：首轮 **MBTI**；二轮补 **16PF**、**EPQ** |
| **兴趣测评** | **霍兰德职业兴趣量表（SDS）** |
| **价值观测评** | **舒伯职业价值观量表（WVI）** |

入口出现两处，须同时接线：
- 首页「生涯趣测」3×3 网格：性格 [html:758]、兴趣 [:764]、价值观 [:770]（`feature-item-9`）
- 「测评」页（`page-assess`）：性格 [:998]、兴趣 [:1008]、价值观 [:1018]（`feat-card`）

> 其余占位入口（情商、领导力、压力/心理、学习风格、团队角色、能力与潜力）本次**不动**，保持 Toast 占位。

## 2. 关键决策（已与用户确认）

| # | 决策点 | 结论 |
|---|---|---|
| 1 | 接入形式 | 全部内置作答（非外链跳转） |
| 2 | 入口结构 | 两级：入口 → 量表选择页 → 逐题作答 → 结果报告页 |
| 3 | 题量规模 | 尽量贴近原版/流传版题量 |
| 4 | 题库文案来源 | 按网络流传经典中文版整理生成（非官方逐字原文；内部原型/演示用途） |
| 5 | 作答交互 | 一屏一题，逐题作答，带进度 |
| 6 | 交付节奏 | 分批：首轮 MBTI + SDS + WVI；16PF、EPQ 二轮补齐（同一引擎追加数据） |

### 版权与免责声明
16PF、EPQ、MBTI、SDS、WVI 均为受版权保护的专业量表。本项目按其结构整理"流传演示版"文案，仅用于内部原型演示；报告页脚注须提示"结果基于整理版，仅供参考，不构成专业测评结论"。公开商用需另行获取正版授权。

## 3. 现状要点（实现须复用的现有结构与风格）

- 全屏滑入容器 `.prediction-overlay`（例：`predictionPage` id 在 [html:1246]、`careerPlanPage` [:1373]），内含 `.status-bar` + `.pred-header`（`.pred-header-back` / `.pred-header-title` / `.pred-header-close`）+ `.pred-body`（可滚动内容）。
- `timeecho-overlay` 用于结果类页面（`careerResultPage` [:1588]），内含 `te-*` 展示样式：`te-skill-bar` / `te-skill-bar-fill`、`te-anchor-tag`、`te-theme-card`、`te-tl-tag` 等。
- 卡片与入口：`.feat-card` + `.feat-card-icon fi-*` + `.feat-card-title/desc/arrow`。
- 选项组件：`.cp-choice-row` / `.cp-choice`（选中 `.active`，黑底白字）；chips：`.cp-chip`。
- 主题色 `fi-*`：性格=橙 `fi-orange`、兴趣=蓝 `fi-blue`、价值观=绿 `fi-green`（现有图标配色即此三色，继续沿用）。
- 入口图标/文案已在占位卡片中定义，接线时尽量复用其 SVG 图标。
- 测评报告静态示例区块：`page-assess` 中 `.section-title "测评报告"` + 一条静态"性格测评报告 · INTJ"卡片 [html:1088-1097]。
- JS 均为 IIFE 内 `window.xxx = function(){}` 挂载（入口回调用内联 `onclick`）。`page-assess` 无独立 tab，由 `openAssess()` [:2130] 切入。

## 4. 新增架构：数据驱动的通用测评引擎

### 4.1 三层 UI（复用 `.prediction-overlay` 全屏容器 + `.pred-header` + `.pred-body`）

新增 3 个全屏容器：

1. **`scalePage`（量表选择层）** —— 按分类（`personality` / `interest` / `value`）列出该分类下的量表卡片：
   - `.pred-header`：返回关闭；标题 = 该分类名称（如"性格测评"）。
   - `.pred-body`：分类一句话简介 + 量表卡片列表。每张卡片复用 `.feat-card`：`fi-*` 图标、量表名、副标题（题数 · 预计约 X 分钟）、右侧箭头/开始。
   - 点击量表卡片 → `openQuiz(scaleId)`。

2. **`quizPage`（逐题作答器）** —— 一屏一题：
   - `.pred-header`：返回（`closeQuiz`，弃当前会话）+ 量表名。
   - 进度区：`第 {n} / {N} 题` + 进度条（复用 `te-skill-bar` 或新增同风格细条）。
   - `.pred-body`：题干 + 选项组。选项均为**单选**：
     - MBTI：两个陈述句按钮（二选一）。
     - SDS：`喜欢 / 不喜欢` 两个按钮。
     - WVI：5 级同意度（1 非常不赞同 … 5 非常赞同）。
   - 底部操作条：`上一题`（禁用态处理）/ `下一题`；当前题**未作答不可进下一题**（轻提示）。最后一题按钮文案为 `提交并查看结果`。
   - 支持中途「上一题」改答（覆盖原选择）。

3. **`quizResultPage`（结果报告页）**：
   - `.pred-header`：返回 = 关闭结果回到上一层（量表选择页）；标题 = 量表名 + 结果摘要。
   - 报告正文按各量表 `render` 输出，统一风格复用 `te-*` / `cr-*` 样式（维度条形、标签、卡片式解读）。
   - 底部：`重新测试`（清空该套会话重新答）/ `完成`（关闭并回到所在页面）。

### 4.2 数据与计算模型（五套共用）

```js
// 量表统一结构
{
  id: 'mbti' | 'holland' | 'wvi',
  cat: 'personality' | 'interest' | 'value',
  name: 'MBTI 性格类型测评', short: 'MBTI',
  icon: '<svg...>',            // 复用现有对应 SVG
  color: 'fi-orange' | 'fi-blue' | 'fi-green',
  desc: '一句话简介', minutes: 8,
  intro: '开始页/量表卡片下的引导文案',
  questions: [ { text, opts:[...], dim } ],
  scoring: function(answers) -> { dims:{}, code?, ... },
  render: function(result) -> { primaryTitle, primarySub, badge,
           bars:[{name,a,b,aLv,bLv}], sections:[{title,html}],
           advice:[...] }
}
```

- 作答器仅依赖 `questions`（全单选：`{text, opts}`）与 `answers`（`{ [题号]: 选项下标 }`）。
- 每套计分/渲染写在各自配置内；**新增量表 = 追加一份该结构数据，不改引擎**。

### 4.3 第一轮题库说明（文案在实施时按流传经典版整理生成）

| 量表 | 题量与结构 | 作答 | 输出报告 |
|---|---|---|---|
| **MBTI** | 4 维（E/I、N/S、T/F、J/P）均衡题，约 64 题；每维末尾含 1 道主观倾向题作为**平分 tie-break** | 二选一句 | 4 字母类型码 + 16 型画像（名称/关键词/适合方向） |
| **霍兰德 SDS** | 6 型（R/I/A/S/E/C）各约 10 项，约 60 题 | 喜欢 / 不喜欢 | RIASEC 六型得分条形 + Top3 字母码 + 主型职业方向参考 |
| **舒伯 WVI** | 15 种价值观 × 3 题 = 45 题 | 1–5 同意度 | 15 维得分条形 + Top3 价值取向解读 |

MBTI 16 型描述、SDS 六型/职业参考、WVI 15 维（成就感、物质保障、生活方式、社会声望、工作环境、同事关系、经济报酬、社会交往、智力刺激、利他主义、创造性、独立性、多样性、安全感、管理权力）的解读文案在实施中编写为精简演示版；维表最终以题库为准并保持命名统一。

## 5. 与「测评报告」联动

- 采用 `localStorage`（key 如 `zj_assess_reports`）保存最近/各次完成记录：`{ scaleId, name, summary(如 INTJ/类型或 Top3), doneAt }`。
- 将 `page-assess` 的静态"测评报告"区块 [html:1088-1097] 改造为**动态列表**：有记录时渲染最近若干条（复用该卡片样式 + `查看报告` 徽标），无记录时显示空态文案。
- 范围外：不新建"个人中心 → 测评报告"历史详情页（该菜单保持 Toast 占位），避免范围膨胀。

## 6. 会话、边界与异常

- 作答会话为内存态 `{ scaleId, answers, idx }`，随打开开始、中途关闭丢弃（与现有原型行为一致，不做跨会话持久）。
- 必答校验：未答当前题不可前进；全部答完才可提交。
- 改答/返回：上一题改答直接覆盖。
- 重新测试：重置该套 answers 从第 1 题开始。
- 提交后直接进入结果页并同步写入报告记录。
- 异常兜底：找不到量表配置时 `showToast` 提示且不崩溃；结果无 `localStorage` 可用时仅不落库、不阻塞展示。

## 7. 验证

静态单文件无构建/单测链，采用浏览器实测（Playwright）逐套走通：

1. 首页与测评页两处入口均能进入对应量表选择页，且分类/量表映射正确（性格=MBTI、兴趣=SDS、价值观=WVI）。
2. 每套全流程：选量表 → 逐题作答 → 必答拦截 → 改答 → 返回 → 提交 → 报告页渲染。
3. 结果数值与按 `scoring` 手算抽查一致（如 MBTI 字母方向、SDS 六型计数、WVI 维和 Top3）。
4. 「测评报告」区块随完成联动刷新，空态正确。
5. 其余占位入口（情商/领导力等）行为无回归。
6. 视觉与现有 UI 一致（全屏容器、fi 主题色、卡片、进度条、报告条）。

## 8. 验收标准

- [ ] 三个入口（两处入口位）均可进入两级流程，映射无误。
- [ ] MBTI / 霍兰德 SDS / 舒伯 WVI 全流程可答、可出报告。
- [ ] 必答、改答、返回、重新测试行为正确。
- [ ] 报告数值手算一致，文案含"整理版，仅供参考"提示。
- [ ] 测评报告列表联动刷新，无记录时空态正常。
- [ ] 其它入口无回归；整体风格与原 UI 一致。

- 量表信度/效度的科学校验。
- 16PF、EPQ（第二轮单独实施）。
